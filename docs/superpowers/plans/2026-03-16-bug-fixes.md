## Chunk 1: Critical Crashes

### Task 1: Fix `addCSS` — `removeCSS` crashes when element already exists

**Files:**
- Modify: `src/contents/util/dom/css.ts:25-38`

**Root cause:** `let style: HTMLStyleElement` is declared but never assigned when `document.getElementById(id)` finds an existing element. The returned closure calls `style.remove()` → TypeError.

- [ ] **Step 1: Open and read the file**

  Read `src/contents/util/dom/css.ts` to confirm current state matches the bug.
  Expected: `let style: HTMLStyleElement` on line 26, only assigned inside `if` block.

- [ ] **Step 2: Apply the fix**

  Replace the entire `addCSS` function with:

  ```typescript
  export const addCSS = function(css: string, id: string): () => void {
    let style = document.getElementById(id) as HTMLStyleElement | null
    if (!style) {
      style = document.createElement('style')
      style.type = 'text/css'
      style.id = id
      style.textContent = css
      document.head.appendChild(style)
    }
    return () => style!.remove()
  }
  ```

  Key change: `style` is now assigned on the first line (always resolves existing element or creates new). Non-null assertion `style!` in closure is safe because both branches guarantee assignment.

- [ ] **Step 3: Verify manually**

  In browser DevTools console on any page with extension loaded:
  ```javascript

  const rm1 = window.__addCSS?.('body{}', 'test-id')
  const rm2 = window.__addCSS?.('body{}', 'test-id')  // element already exists
  rm2?.()  // must not throw
  ```
  Or: open Medium article, open TOC, close TOC, open again — no console errors.

- [ ] **Step 4: Commit**

  ```bash

  git commit -m "fix: addCSS removeCSS crash when element already exists"
  ```

### Task 2: Fix RSS parsing — crash on `links[1]` / `links[2]` out of bounds

**Files:**
- Modify: `src/background.ts:117-164`

**Root cause:** `links[1].match(...)` and `links[2].match(...)` crash with TypeError when the article page has fewer than 3 links matching the article ID query. The fix replaces positional access with semantic `.find()` + optional chaining.

- [ ] **Step 1: Read the affected section**

  Read `src/background.ts` lines 110-175 to confirm current state.
  Expected: `const link1 = links[1].match(...)` on line 117, `const link2 = links[2].match(...)` on line 118.

- [ ] **Step 2: Apply the fix**

  Replace lines 117–164 (from `const link1 = ...` through the closing `}` of the `if (link1.includes('@'))` block) with:

  ```typescript
  // Semantic search — safe regardless of link count or order
  const userFeedLink = links.find(
    (l) => l.includes('/feed/@') || /\/feed\/?(?:\?.*)?$/.test(l)
  )
  const pubFeedLink = links.find(
    (l) => l.includes('/feed/') && !l.includes('/feed/@')
  )

  // Optional chaining throughout — never crashes on undefined
  const userPath = userFeedLink?.match(/\/\/([^?]+)/)?.[1] ?? null
  const pubPath  = pubFeedLink?.match(/\/\/([^?]+)/)?.[1] ?? null

  // Normalise: ensure userFeed ends with /feed
  const userFeed = userPath
    ? userPath.includes('/feed') ? userPath : userPath.replace(/\/?$/, '/feed')
    : null

  const mediumPublication =
    pubPath?.match(/medium\.com\/([^?/]+)/)?.[1] ?? null
  const publicationDomain =
    !mediumPublication && pubPath ? pubPath : null
  ```

## Chunk 2: Medium Bugs

### Task 3: Fix `lastUrl` — shared across tabs, second tab skips RSS detection

**Files:**
- Modify: `src/background.ts:82-91`

**Root cause:** `let lastUrl = ''` is a module-level singleton. When any tab updates, `lastUrl` is overwritten, causing subsequent updates from other tabs with the same URL to be skipped.

- [ ] **Step 1: Replace `lastUrl` with a per-tab Map**

  Find line 82: `let lastUrl = '';`
  Replace with:
  ```typescript
  const lastUrlByTab = new Map<number, string>()
  ```

  Then add the following at module scope, immediately after the closing `})` of the `chrome.tabs.onUpdated.addListener` block (which ends around line 190):
  ```typescript
  // Module scope — clean up per-tab state when a tab closes
  chrome.tabs.onRemoved.addListener((tabId) => {
    lastUrlByTab.delete(tabId)
  })
  ```

  Inside `chrome.tabs.onUpdated.addListener`, replace:
  ```typescript
  if (changeInfo.status === 'complete' && tab.url && tab.url !== lastUrl) {
    lastUrl = tab.url;
  ```
  with:
  ```typescript
  if (changeInfo.status === 'complete' && tab.url && tab.url !== lastUrlByTab.get(tabId)) {
    lastUrlByTab.set(tabId, tab.url)
  ```

- [ ] **Step 2: Verify build**

  Expected: no TypeScript errors.

- [ ] **Step 3: Verify manually**

### Task 4: Fix inner MutationObserver shadow and leak in `trackArticle`

**Files:**
- Modify: `src/contents/index.ts:157-158, 236-247, 298-308`

**Root cause:** `trackArticle()` declares `const observer = new MutationObserver(...)` (line 236) which shadows the outer `let observer` (line 157). Calling `unload()` disconnects only the outer observer; the inner ones accumulate if `unload()` is called before the article finishes loading.

- [ ] **Step 1: Add `innerObserver` module-level variable**

  Near line 157, alongside `let observer: any = null;`, add:
  ```typescript
  let innerObserver: MutationObserver | null = null
  ```

- [ ] **Step 2: Replace inner `const observer` in `trackArticle`**

  Inside `trackArticle()`, replace:
  ```typescript
  const observer = new MutationObserver((mutations, obs) => {
    const articleLoaded = document.querySelector(articleClass);
    if (articleLoaded) {
      start();
      obs.disconnect();
    }
  });

  observer.observe(document, {
    childList: true,
    subtree: true
  });
  ```
  with:
  ```typescript
  if (innerObserver) {
    innerObserver.disconnect()
    innerObserver = null
  }
  innerObserver = new MutationObserver((mutations, obs) => {
    const articleLoaded = document.querySelector(articleClass)
    if (articleLoaded) {
      start()
      obs.disconnect()
      innerObserver = null
    }
  })
  innerObserver.observe(document, { childList: true, subtree: true })
  ```

- [ ] **Step 3: Clean up `innerObserver` in `unload()`**

  Inside `unload()` (around line 298), after the existing `observer.disconnect()` block, add:
  ```typescript
  if (innerObserver) {
    innerObserver.disconnect()
    innerObserver = null
  }
  ```

  ```bash

  ```
  Expected: no TypeScript errors.

  Open Inoreader or Medium, open an article, then quickly click the extension toggle to unload while the article is still loading.
  Expected: no lingering MutationObserver callbacks firing after unload (check DevTools → Performance → observe no callbacks after unload).

### Task 5: Fix `renderToc` — retry timer race condition

**Files:**
- Modify: `src/contents/index.ts:66-130`

**Root cause:** The 500ms retry `setTimeout` inside `renderToc` is not tracked. If `renderToc` is called again before the timer fires, both timers run and can create duplicate TOC instances.

- [ ] **Step 1: Add `retryTimer` at module scope**

  After line 70 (`let toc: Toc | undefined`), add:
  ```typescript
  let retryTimer: ReturnType<typeof setTimeout> | null = null
  ```

- [ ] **Step 2: Cancel stale timer at start of `renderToc`**

  At the very top of `renderToc`, before `if (toc) { toc.dispose() }`, add:
  ```typescript
  if (retryTimer) {
    clearTimeout(retryTimer)
    retryTimer = null
  }
  ```

- [ ] **Step 3: Store timer reference in the retry setTimeout**

  Replace:
  ```typescript
  setTimeout(() => {
  ```
  with:
  ```typescript
  retryTimer = setTimeout(() => {
    retryTimer = null
  ```
  and close the new block properly (add `retryTimer = null` as the first line inside the callback).
